## Human checks before presenting

- Read the three-minute and five-minute scripts aloud and time the actual clicks. Timings are targets, not a certified student rehearsal.
- Confirm laptop/projector sound output, volume, unmuted browser and installed English/Hindi/Marathi/Korean voices. Listen to the actual samples with fluent reviewers; callbacks do not prove pronunciation.
- Confirm power, disk space, browser profiles and local Docker services; keep the laptop awake. Recheck status after a restart.
- Confirm each tab is the same fictional school/date. Do not show unrelated historical records or accumulated QA classes.
- Explain draft versus finalized attendance, pending versus synced, and mock versus physical reader before showing them.
- Review the financial assumptions and sourced preliminary competitor table. Do not invent sales, partnerships, certification or validated demand.

## If something fails

| Failure | Honest recovery |
|---|---|
| Audio silent | Stop playback; read the original aloud. State that speaker output needs checking. Do not call a progress bar audible proof. |
| Internet unavailable | The already running loopback stack may continue. Do not promise public family delivery or browser-only offline use. Use the extracted backup if needed. |
| Local server/database unavailable | Stop the live claim. Show dated recorded screenshots; restart only owned services through the documented workflow. Never reset the database to recover a pitch. |
| Mock scanner fails | Explain it is simulated and show saved queue evidence. Manual classroom attendance still works; never equate a scan with safety or attendance. |
| Attendance conflict/held work | Explain why the older write is held. Use the authorized resolution workflow, or retain it; do not force overwrite for presentation. |
| Fixture date is old | Explicitly clean only the known owned rehearsal, then start a new dated fixture. Historical school messages remain unchanged. |

## Stop and scoped cleanup

```powershell
npm run competition -- stop
# Retains the owned fictional fixture for later same-day restart.
npm run competition -- start

# After inspecting any pending work; discards only this owned rehearsal's work:
npm run competition -- clean --discard-pending
```

`clean` without the flag refuses unresolved pending/attention work. Backups are retained. Unknown fixture markers/process ownership are refused. Do not delete private journals or use blanket database cleanup. The fully automated acceptance command, `npm run verify:competition`, requires no existing rehearsal, owns its own fixture/processes and cleans them afterward.
